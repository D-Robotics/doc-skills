# ai-review — AI 辅助 review

TW 人审之前，用统一 prompt 跑一遍文档，AI 只查四个 skill 和 CI 都查不了的东西——行文逻辑、信息架构、内容质量。机械项（术语/格式/结构/步骤）由四个 skill 兜底，AI review 不重复查。

## 使用方式

```bash
/ai-review overview.md burn-sd-card.md
```

## 检查范围

### 行文逻辑

- 段落之间是否有逻辑跳跃——上一段讲 A，下一段讲 C，中间缺了 B
- 前置知识是否在引用前已介绍——"配置网络"出现在"网络概念介绍"之前
- 是否有冗余重复段落——同一件事在两个地方各说了一遍

### 步骤完整性（操作类文档）

- 是否有"前提条件"章节——读者需要准备什么
- 是否有"预期结果"说明——做完这一步应该看到什么
- 异常分支是否覆盖——做错了怎么办

### 内容质量

- 表述是否清晰——有没有"适当调整"、"按需配置"这种模糊表述
- 概念是否在首次出现时解释——"BPU"第一次出现时有没有全称
- 中英文术语是否混用——同一概念一会叫"烧录"一会叫"flashing"
- 鼠标操作是否使用规范写法——"单击"（非"点击"）、"双击"（非"连点两下"）、"悬停"（非"鼠标放在"），对照 [writing-style-guide §4.2](writing-style-guide.md)

## 输出格式

```text
🔍 AI review 结果（共 N 处可疑点）

💡 行文逻辑（2 处）
  15: "配置网络"出现在网络概念介绍之前，建议先介绍再讲配置
  42: 第 3 段和第 7 段重复描述了 eMMC 分区，建议合并

💡 步骤完整性（1 处）
  8: 缺少"前提条件"——读者需要知道准备什么硬件

💡 内容质量（1 处）
  23: "适当调整波特率"模糊，建议写实为"设置为 115200"
```

## 与四个 skill 的分工

| | 四个 skill（term-check 等） | AI review |
|---|---|---|
| 查什么 | 术语/格式/结构/步骤机械项 | 行文逻辑/信息架构/内容质量 |
| 谁用 | 研发提 PR 前 | TW 人审前 |
| 判定 | 机械判定，对就是对 | 标可疑点，人判断 |
| 频率 | 每篇都跑 | 每篇都跑 |
