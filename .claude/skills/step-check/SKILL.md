# step-check — 步骤自检

检查操作步骤类文档的写法规范。适用于烧录、安装、配置等 How-to 类文档。

## 检查规则

### 标题

- 操作类文档的标题用「动词+宾语」：`使用 XBurn 烧录系统镜像` ✅，`烧录步骤` ⚠️（侧边栏对仗时可例外）
- 标题不要用 `设置方法如下` / `步骤如下` 这类冗余引导语

### 步骤编号

- 步骤用有序列表（1. 2. 3.），编号连续不跳号
- 同一任务内的子步骤连续编号，不要把"设置项"和"执行操作"分成两段平级列表

### 控件标注

- 界面控件名（菜单/按钮/下拉框）加粗：**产品类型**、**开始升级**
- 控件里选的值用行内代码：`secure`、`usb`、`eMMC`
- 硬件位号（开关/按键/指示灯）用链接指向硬件介绍页，不用行内代码

### 图片缩进

- 步骤下的图片必须缩进至步骤下一级（3 空格），不能顶格
- 顶格图片会脱离步骤上下文，Docusaurus 渲染时与步骤分离

### 异常分支

- 异常情况（识别不到设备/报错/未达预期）用 `:::note` 或 `:::warning` 包住，挂在对应步骤后
- 异常分支不要与步骤平级平铺

### 模糊表述

- 不允许模糊表述：`数据传输质量高` / `长度越短越好` / `适当调整`
- 应写实：`支持数据传输（非纯充电线）` / `建议 1 米以内` / `设置为 115200`

## 忽略

- 非操作类文档（概念说明、API 参考、FAQ 等）
- 代码块内的内容

## 输出示例

```text
✅ step-check 通过，未发现步骤写法问题。
```

```text
❌ step-check 发现 3 处步骤写法问题：

  5: 标题 "烧录步骤" 建议改为动词开头，如 "烧录系统镜像"
  18: 图片未缩进，第 18 行顶格，应缩进 3 空格
  35: 模糊表述 "长度越短越好" → 建议写实为 "建议 1 米以内"
```
